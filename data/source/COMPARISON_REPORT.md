## 결론 먼저

**기준 자료 A·D를 받지 못해, 대조를 마치지 못했다.** 이 환경의 네트워크 정책이 해당 호스트를 막았다.

- 그래서 판정 원칙상 **`master_120.csv`와 `master_20.csv`는 만들지 않았다.**
  - 기준본 없이 B만으로 '확정 원문'을 만들면 판정 원칙에 어긋난다.
- 확보한 자료 B(120문항)와 원고 부록 A(20문항)는 각각 **내부 구조 점검**을 모두 통과했다. 이것은 기준본 대조가 아니다.
- 다음 진행 방법은 아래 4절 '미결'에 정리했다.

## 4. 미결 목록 (대표님 판단 필요)

1. **기준본 A·C·D를 어떻게 확보할까**
   - (가) 클라우드 환경 네트워크 허용 목록에 세 호스트를 추가한다: `bpb-us-e1.wpmucdn.com`, `www.psychology.uga.edu`, `ipip.ori.org`. 추가되면 바로 받아서 다시 대조한다.
   - (나) 대표님이 세 파일을 직접 받아 GitHub 웹으로 `data/source/`에 올린다. 파일 이름은 SOURCES.md에 적어 두었다.
2. **A가 오기 전에 B로 임시 진행할까**
   - 120문항은 B만으로도 구조 점검을 통과한다. 그래서 B를 '임시 기준(A 대조 대기)'으로 표시한 `master_120.csv`를 먼저 만들 수 있다. 2단계 채점 엔진과 검사 화면 작업도 앞당길 수 있다.
   - 이 경우 A가 오면 같은 스크립트로 다시 대조한다. 어긋나는 곳은 A대로 고친다.
   - 판정 원칙에서 벗어나는 일이므로 승인 없이 하지 않았다.
3. **20문항 영문 원문**
   - D 없이는 `text_en`을 원문 근거로 채울 수 없다.
   - 부록 A의 한국어 문항·순서·방향만으로 `master_20.csv`를 만들고 `text_en`은 비워 둘지, D를 기다릴지 정해 주셔야 한다.
